## 0. 全景：用户旅程四问

| 问题（业务视角） | 维度 | 表 |
| --- | --- | --- |
| 来了的人还回不回来？ | 时间维度的漏 | `ads_user_retention`（d1/d3/d7） |

## 2. 口径体系：七条声明 + 一条补（要点）

| # | 声明 | 核心内容 |
| --- | --- | --- |
| 一 | 双口径 | 金额类指标两套：**全部订单** vs **仅已完成**。王五两口径差数倍——口径不同结论相反 |
| 二 | 聚合不可逆 | `dws_user` 按 user_id GROUP BY 后 `order_date` 只剩 first/last 两个端点，每日明细回不来；日粒度指标必须回 `dwd_order` 现算 |
| 三 | 复购率 | **订单数法**（同日多单也算复购，简化口径）；分母 = 当月有已完成订单的用户（**9 人**，周九 109 单已退款不计） |
| 四 | 精度 | `ROUND(x, 4)` |
| 五 | 留存 | ① cohort 按**首单日**归属 ② **宽进严出** ③ **未观测 ≠ 零**：窗口超出地平线填 **NULL** ④ 地平线随重跑生长 |
| 五·补 | d14/d30 扩展条件 | 当前**不建列**：horizon 08-11 与最早首单 08-01 仅差 10 天 < 14/30。列级触发 / 行级判据分离，不占位 |
| 六 | 分层 | ① 金额仅已完成 ② 固定阈值，边界带等号归高档 ③ 新用户优先级最高 ④ 码值字典 |
| 七 | 漏斗 | ① 两步（数据资产限制）② 分母任意状态 ③ 分子按人 ④ 顺序免费 ⑤ 全 horizon 一口钟 |

## 3. 口径治理三原则

**① 口径是承诺，不是描述。** d7 承诺「7 天内」，第 8 天回来不违约、只是不在承诺范围。若按「数据能看到几天就算几天」改口径，同一列每行口径不同，横向不可比、纵向不可加，整列报废。信息不浪费的解法是加 d14 / 回访间隔分布表（指标家族），不是改 d7。

**② 文档撒谎比没文档更毒。** 公式列 = 跑通代码原样复制；字段名列 = DDL 契约逐字一致；业务含义列答「这是什么」，公式列答「怎么算」；文档里的每个词都要能在表/代码里找到对应物。

**③ 登记三判据 + 七列格式 + DRY。** 键列/搬运列不登；上游已登记指标不重复登；算出来的派生列才登。七列：指标名称 / 字段名 / 业务含义 / 计算公式 / 来源表 / 粒度 / 口径。

## 4. 验收四刀 + 两个工具

1. **预期表**——跑数前先写预期值（如漏斗 10/9/0.9/1），跑后逐格对；
2. **守恒对账**——行内 `lost = order − finish`；表级 `SUM(cohort_cnt) = COUNT(DISTINCT user_id)`；
3. **边界样本穿透**——王五（一完成一取消）、周九（唯一单退款）；
4. **独立路径**——Python 预演 / 心算复现（9/10=0.9），两条路走同一个数。

**验钞机**：`conv_rate > 1`、`d7 < d3`、`rate ∉ [0,1]` → 一秒识破。**静默 bug 检测**：同质数据下两种写法结果相同 → 必须靠边界样本翻车。

## 5. 面试话术（每段 30 秒）

- **复购率**：月度、仅已完成；分子 = 当月已完成单 ≥2 的用户，分母 = ≥1 的用户，按人不按订单；订单数法简化口径。
- **留存率**：按首单日切 cohort，宽进严出；分子 = 首单后 1~7 天内（含第 7 天）有已完成订单，首单当天不算；窗口没跑完填 NULL 不填 0；d1/d3/d7 共用分母，分母封盘。
- **分层**：固定阈值 + 天然断层定档；边界带等号归高档；新客保护期优先级最高；一个 CASE WHEN 按优先级出五档码。
- **漏斗**：两步（下单→完成），因为数据只有订单状态无埋点；宽进严出、按人、顺序免费、全 horizon 一口钟；10 人 9 完成 90%，漏的 1 个是退款大单——**漏斗定位漏点，归因是下一步**。
- **d14 故事**：评估过扩展 d14/d30，当前 horizon 11 天、最大观测 10 天 < 14，建出来全 NULL；登记扩展条件（列级触发/行级判据分离），不占位。**能加是 SQL 问题，该不该加是口径治理问题。**
